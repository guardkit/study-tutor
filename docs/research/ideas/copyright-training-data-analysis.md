## 1. The Problem

The GCSE Study Tutor uses copyrighted educational materials at two points in the pipeline:

1. **Docling ingestion → ChromaDB** (knowledge layer) — Mr Bruff study guide PDFs (commercially purchased, DRM-free) are ingested as RAG chunks
2. **Player-Coach generation loop** (behaviour layer) — the Player agent retrieves these chunks via ChromaDB to generate synthetic training examples in `train.jsonl`

**Critical clarification:** The first fine-tuning run (~1,736 examples, Gemma 4 31B Dense) used **Mr Bruff guides only** as source material. AQA past papers, mark schemes, and examiner reports have been downloaded for reference but were **not** fed into the training data pipeline. This distinction materially changes the risk profile.

The hackathon requires a **public code repository**. The existing strategy already excludes copyrighted source materials from the repo (open-source the pipeline, not the data). The question is whether the *use* of commercially purchased study guides as RAG context for synthetic data generation creates a compliance risk.

### 1.1 The Elephant in the Room

Every frontier AI model — Claude, GPT, Gemini, Gemma — was trained on copyrighted works at massive scale, largely without explicit permission from rights holders. The Gemma 4 model that this hackathon is built around was trained on data that almost certainly includes copyrighted books, articles, and creative works. The legal battles (NYT v OpenAI, Authors Guild cases) are ongoing and unresolved.

A solo developer building a GCSE tutor for his daughter is being asked to navigate copyright constraints that the companies running $200K hackathons have not themselves resolved. This asymmetry should be acknowledged honestly in any submission — not as an excuse, but as context for the real-world constraints that education AI projects face.

## 2. AQA's Position: Explicit Prohibition

AQA's Copyright & Intellectual Property Policy is unambiguous:

> "AQA does not permit the use of any AQA material in any manner or for any purposes in connection with the training of Artificial Intelligence powered tools or technologies."

> "AQA will not allow the use of any AQA material in or on any edition of a third-party work where any part of that work is generated or produced using Artificial Intelligence or similar tools or technologies."

**Source:** https://www.aqa.org.uk/about-us/who-we-are/our-standards/copyright-and-intellectual-property-policy

This is a broad prohibition — "any manner or for any purposes in connection with" — which on its face covers:

- Using AQA past papers as RAG context for synthetic data generation ✗
- Using AQA mark schemes to inform the Coach's evaluation rubric ✗
- Using AQA examiner reports as source material for tutoring behaviour ✗
- Fine-tuning a model on synthetic data that was generated with reference to AQA materials ✗ (arguable)
- Using AQA specifications to understand curriculum structure ✗ (arguable — but this is what every teacher and textbook author does)

Additionally, AQA explicitly prohibits use of their materials on YouTube or social media platforms, which is relevant to the demo video requirement.

**Important:** AQA materials (past papers, mark schemes, examiner reports) have been downloaded for reference and future RAG knowledge layer use, but they were **not** used in the training data pipeline. The first fine-tuning run used Mr Bruff study guides exclusively. AQA's prohibition is noted here as a constraint on future pipeline expansions and on any use of AQA content in the knowledge layer at inference time.

## 3. Mr Bruff Study Guides: What Was Actually Used

Mr Bruff guides are commercially purchased, DRM-free PDF study guides. They were the **sole source material** for the first training run. No scanning or DRM circumvention was involved — these are digital products sold as PDFs, purchased legitimately, and processed through Docling's standard PDF mode.

### 3.1 What Happened in the Pipeline

1. Mr Bruff PDFs purchased (DRM-free digital download)
2. Docling processed the PDFs into text chunks
3. Chunks ingested into ChromaDB as RAG context
4. Player-Coach adversarial loop retrieved chunks to generate synthetic tutoring conversations
5. Coach validated quality against GOAL.md criteria — rejecting and forcing regeneration of pedagogically poor examples
6. Accepted examples written to `train.jsonl` in ShareGPT format
7. `train.jsonl` used to fine-tune Gemma 4 31B Dense via Unsloth

**The output (`train.jsonl`) is original synthetic content.** It contains invented tutoring conversations — student questions, tutor responses, Socratic dialogue, essay feedback — generated by the Player agent. The Mr Bruff content informed the *curriculum accuracy* of those conversations, but the conversations themselves are not reproductions of Mr Bruff's text.

### 3.2 Three Layers of Synthetic Transformation

This is where the Player-Coach adversarial loop creates significant transformative distance from the source material. The pipeline doesn't just reformat Mr Bruff's prose — it introduces three distinct layers of transformation that produce something that never existed in the original:

**Layer 1: Content transformation — static prose → interactive dialogue**

Mr Bruff's guides are written as revision prose: "When analysing Macbeth's soliloquy, consider how Shakespeare uses iambic pentameter to convey inner turmoil." That's a static reference text that tells you facts about literature.

The Player agent transforms this into a multi-turn tutoring conversation where a student asks a confused question, the tutor probes their understanding, guides them through analysis step by step using Socratic questioning, provides scaffolded feedback aligned to specific assessment objectives, and adjusts its language to the student's grade level. This conversational form — the pedagogical interaction — doesn't exist anywhere in the source material.

**Layer 2: Structural transformation — reference text → ShareGPT with reasoning blocks**

Each training example in `train.jsonl` is structured as a ShareGPT conversation with a metadata schema:

- `messages: [{role: "user", content: "..."}, {role: "assistant", content: "..."}]`
- 75% of assistant responses include a `<think>...</think>` reasoning block where the tutor reasons about which assessment objective the student is struggling with, what misconception is being revealed, and what pedagogical approach to take before responding
- Metadata includes `layer`, `type`, `ao` (assessment objective), `topic`, `grade_target`, and `source`

Mr Bruff never wrote `<think>` reasoning blocks. The internal pedagogical reasoning is entirely synthetic — it teaches the fine-tuned model *how to think about tutoring*, not just what to say.

**Layer 3: Quality transformation — adversarial Coach validation**

The Coach agent evaluates every Player-generated example against the GOAL.md evaluation criteria, returning a structured JSON assessment: `{decision, score, issues, criteria_met, quality_assessment}`. Examples that are factually correct but pedagogically poor — too much telling and not enough questioning, scaffolding at the wrong level, assessment objective misalignment — get rejected. The Player must revise and resubmit, or the example is discarded entirely.

This means the output isn't just "Mr Bruff's content in a different shape." It's content that has passed through an adversarial quality gate that evaluates tutoring effectiveness — a filter the source material itself was never subjected to. The Coach creates a selection pressure that shapes the training data toward pedagogical quality, not just curriculum accuracy.

**The cumulative effect:** The `train.jsonl` contains multi-turn Socratic tutoring conversations with internal reasoning blocks, AO-aligned scaffolding, and adversarially validated pedagogical quality. The Mr Bruff guides provided the curriculum knowledge that made those conversations factually grounded. But the form, the pedagogy, the interaction patterns, the reasoning structure, and the quality threshold are all contributions of the Player-Coach pipeline.

### 3.3 The Human Tutor Analogy (Extended)

A human tutor reads Mr Bruff's Macbeth guide, absorbs the analytical frameworks and curriculum content, and then teaches a student through interactive conversation. The tutor's teaching is informed by the study guide but doesn't reproduce it. The tutor adds pedagogy — Socratic questioning, adaptive scaffolding, formative assessment — that the study guide doesn't contain. No one would argue the tutor's teaching infringes Mr Bruff's copyright.

The Player-Coach pipeline does the same thing computationally: the RAG retrieval is the "reading," the Player's synthetic generation is the "teaching," and the Coach's adversarial validation is the "professional development" that ensures teaching quality. The output is as far from the source material as a tutor's lesson is from the textbook they studied.

The legal question is whether the computational intermediary changes this analysis. That's unsettled law. But the transformative distance is real and substantial.

### 3.4 Why This Is a Stronger Position Than It First Appears

- **Legitimate purchase** — the PDFs were bought, not pirated or scraped
- **DRM-free** — no circumvention of technical protection measures (no DMCA / UK anti-circumvention issue)
- **No redistribution** — the Mr Bruff PDFs are not in the public repo and never will be
- **Three layers of synthetic transformation** — content (prose → dialogue), structural (text → ShareGPT + reasoning blocks), and quality (adversarial Coach validation)
- **Fundamentally different purpose** — the source is a static revision guide; the output is interactive tutoring conversations with internal pedagogical reasoning
- **No explicit AI prohibition** — unlike AQA, Mr Bruff's terms do not contain an explicit prohibition on AI use
- **Personal/educational context** — built for one student's GCSE revision, not a commercial product
- **The pipeline is also the technical contribution** — the three-layer transformation is not a copyright workaround, it's the core innovation of the agentic dataset factory. It happens to also create transformative distance.

### 3.5 Where It's Still Grey

- **UK TDM exception (s29A CDPA 1988)** — covers non-commercial research only. A hackathon with a $200K prize pool is difficult to frame as non-commercial.
- **No AI training licence** — Mr Bruff's terms of sale authorise personal educational use, not computational processing for model training.
- **No case law** — there are no UK court decisions on whether using a purchased ebook as RAG context for synthetic data generation constitutes infringement.
- **Scale of copying** — the entire contents of the guides were ingested into ChromaDB, even if the output is synthetic. Whether this intermediate copying is infringing is untested.

### 3.6 The Hypocrisy Context

The Gemma 4 model being used in this hackathon was itself trained on vast quantities of copyrighted text. Google has not obtained explicit licences from every author whose work appeared in the training data. The hackathon is asking developers to build on a foundation that was constructed using the same practices that are legally uncertain for the developers themselves.

This doesn't make copyright infringement acceptable, but it does mean that the *risk posture* should be proportionate. A solo developer using two purchased study guides to train a personal tutor for his daughter is operating at a categorically different scale and intent than a company training a foundation model on the entire web.

**UK legal position (as of April 2026):** The government published its Report on Copyright and AI on 18 March 2026, adopting a "wait and see" approach. The existing TDM exception (s29A CDPA 1988) covers only non-commercial research. No broad commercial TDM exception has been enacted. The House of Lords Digital and Communications Committee firmly rejected any commercial TDM exception in their March 2026 report. The law is unsettled.

### 4.3 The Critical Distinction

The strongest risk is the intermediate computational copying of Mr Bruff's text into ChromaDB. But this intermediate copy is not distributed, not publicly accessible, and exists for the purpose of generating transformative output. This is a meaningfully different risk profile from, say, publishing the PDFs or reproducing their text verbatim.

For the public repo: the pipeline code and methodology are open-sourced. The source PDFs, ChromaDB collection, `train.jsonl`, and model weights stay private. This is the existing strategy and it holds up well.

## 6. AQA Specification vs AQA Assessment Materials

An important nuance worth documenting:

**AQA Specifications** (e.g., English Language 8700 specification PDF) describe the curriculum structure: what topics are covered, what assessment objectives exist, what skills are tested, how papers are structured. Every teacher, textbook author, and revision guide publisher references these. They are the *definition* of what GCSE English is. Using them to understand curriculum structure is standard educational practice.

**AQA Assessment Materials** (past papers, mark schemes, examiner reports) are creative/analytical works that demonstrate how the specification is assessed. These are what AQA's AI prohibition is primarily targeting — they don't want AI systems trained to reproduce their assessment content.

**For the GOAL.md:** It's reasonable and defensible to reference AQA assessment objectives by name and number (AO1, AO2, etc.), describe what skills they test, and instruct the tutor to align its teaching to them. This is no different from what any GCSE textbook does. What's NOT defensible is ingesting actual past paper questions or mark scheme wording as training data.

## 7. Impact on Existing Fine-Tuned Model

The first fine-tuning run (~1,736 examples, Gemma 4 31B Dense) was trained on synthetic data generated from Mr Bruff study guide PDFs (purchased, DRM-free) used as RAG context. **No AQA assessment materials were used in the training pipeline.**

### 7.1 Provenance Chain

```
Mr Bruff PDFs (purchased, DRM-free)
    → Docling PDF extraction (standard mode)
    → ChromaDB chunks (intermediate copy, not distributed)
    → Player-Coach retrieval + synthetic generation
    → train.jsonl (original synthetic conversations)
    → Unsloth fine-tune
    → Gemma 4 31B Dense LoRA adapter
    → GGUF export (Q4_K_M)
    → Ollama deployment on GB10
```

Each step is a further transformation from the source material. The LoRA adapter weights bear no textual resemblance to Mr Bruff's guides — they are numerical adjustments to the model's parameters that encode tutoring *behaviour*, not curriculum *content*.

### 7.2 Risk Assessment

| Scenario | Risk | Rationale |
|----------|------|-----------|
| Use privately for Lilymay | Very Low | Personal, educational, non-commercial. Strongest fair dealing argument. |
| Demo in hackathon video (not distributed) | Low | Showing the model's behaviour, not distributing weights or training data. |
| Upload weights to HuggingFace | Medium | Public distribution of model trained on copyrighted source context. Even though weights aren't text, provenance could be challenged. |
| Include `train.jsonl` in public repo | Medium | Synthetic content, but directly derived from copyrighted RAG context. |
| Include Mr Bruff PDFs in public repo | High | Direct redistribution of copyrighted purchased content. Obviously not acceptable. |

### 7.3 Recommendation

Use the existing model for the hackathon demo. Don't distribute the weights or training data publicly. This is proportionate to the risk and consistent with the "pipeline is open, data is private" strategy.

If the hackathon rules require distributable model weights (unlikely but check), fall back to Option B — a clean training run takes ~2 hours on GB10.
