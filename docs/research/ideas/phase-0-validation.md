## What drifted

Three pieces drifted without invalidating the plan; each is captured in a recorded decision rather than left as silent slip.

- **The "six parity surfaces" framing extended to fourteen cross-cutting concerns.** ADR-ARCH-018 (2026-04-27) promoted SR-08 → CC-13 (Graphiti async write-back at every write point) and SR-09 → CC-14 (runtime LLM parameters `num_ctx` / `num_predict` explicit). The original six SRs are still load-bearing exactly as the scope said; the load-bearing set is now larger. CC-09 through CC-14 were added without invalidating CC-01 through CC-08. Three follow-on `/system-design` runs (MCP Transport AM, Tutoring PM, Inference Runtime PM-late on 2026-04-27) refreshed all three Phase-0-context contracts to absorb the new CCs, producing DDR-001 / DDR-002 / DDR-003 / DDR-004.
- **`tutor_session_end` async-write-back broadened.** The scope's SR-07 table classified `tutor_session_end` as "sync — triggers async Graphiti write-back" (single write site at session-end). ADR-ARCH-019 supersedes ADR-ARCH-003 and broadens the rule: every Graphiti write point is async-from-caller, including `tutor_turn` mid-session writes (Coach-observed misconceptions, planner topic-confidence updates). The original classification still holds; the rule is more general than the table assumed. DDR-002 pinned write ownership across the now-three flush points (F1 Coach / F2 planner / F3 session-end); DDR-003 decoupled `session.completed` event emission from Graphiti write success.
- **Numeric / runtime drift absorbed during the empirical week.** `OLLAMA_NUM_PREDICT` capped at 2048 (TASK-PO02F-002, commit `7a8a3a3`) and `DEFAULT_OLLAMA_BASE_URL` / `DEFAULT_OLLAMA_MODEL` corrected (TASK-PO02F-003, commit `14afc08`) after the post-smoke defects surfaced. The 23 April OpenWebUI RAG empirical session ([openwebui-rag-empirical-findings-2026-04-23.md](./openwebui-rag-empirical-findings-2026-04-23.md)) added the Modelfile `num_ctx ≥ 16384` / `num_predict ≥ 1500` discipline that became CC-14 and the persona-split (Shakespeare no-RAG vs Modern Texts RAG) that improved Lilymay's experience above the "unchanged" success-criterion floor. None of this contradicted Phase 0 scope; all of it tightened parameters the scope had left implicit. The 27 April Graphiti latency spike measured `add_episode` median 78.98s and `search_nodes` median 0.07s — well beyond the scope's loose budget but consistent with the spike's role as a measurement gate.

## Lessons feeding LES2

Two patterns from Phase 0 worth carrying forward as cross-agent lessons (per the cadence doc's note that "the failure mode that caused [falsified items] should be added to the lessons doc (LES2 round)"):

- **A do-not-cross criterion under a documented contingency is still a falsification at the gate; record both halves.** Bedrock validation's deferral was a sound decision under TASK-CDR-005, but pretending the success criterion was met would erode the validation gate's signal. The gate's value is the honest record, not the green checkmark.
- **"No new DDR expected" predictions about design-refinement runs are unreliable.** The Inference Runtime focus run was scoped as a paste-the-CC-14-rule sweep; the act of deciding *where* the rule lives produced DDR-004. Future `/system-design` focus runs should not pre-commit to "DDR-free" outcomes — the design layer is where the where-does-the-rule-live questions surface, and pinning them is the job.
