# Task: Focused per-task BDD feature file for TASK-NATS-PH1-006

## Description

Workaround for the BDD oracle scope bug identified in
[TASK-REV-CC40](../../../.claude/reviews/TASK-REV-CC40-review-report.md). The Coach's
`independent_tests` path runs `pytest` over the autogenerated step-defs file
`features/nats-fleet-integration/test_nats_fleet_integration.py`, which collects **every**
scenario in the master `nats-fleet-integration.feature` file (30+ scenarios across 9 tasks).
pytest-bdd v8 emits unbound-step scenarios as FAILED, making the gate
`bdd_results.scenarios_failed > 0` deterministically unsatisfiable for any single-task run.

This task ships a **focused per-task feature file + step-defs pair** that contains only the
one scenario TASK-NATS-PH1-006 owns (SIGTERM during in-flight tutor turn). With this in
place, Coach's `independent_tests` for TASK-006 collects exactly one scenario, and the gate
becomes satisfiable.

This is a **demo-deadline blocker** (2026-05-11). Once this lands, the autobuild can resume
via `guardkit autobuild feature FEAT-39E1 --resume` and TASK-006 will approve on turn 1
(implementation already complete at checkpoint `0823395`).

## Lessons

- pytest-bdd v8 emits unbound-step scenarios as **FAILED** rather than the
  `scenarios_pending` status the master glue's docstring assumes. Any Coach BDD oracle
  that uses an un-scoped pytest invocation against a multi-task feature file is
  deterministically un-satisfiable. The proper upstream fix is in GuardKit's
  `bdd_runner` (TASK-FIX-CC-BDD); the per-task focused-file pattern landed here is the
  workaround.
- Python directories with dashes (`nats-fleet-integration`) cannot be imported via
  dotted-path syntax. `importlib.util.spec_from_file_location` is the supported path
  when sibling test files need to share step definitions. Filtering the imported
  module's `dir()` for `test_*` names is required because pytest-bdd's `scenarios()`
  injects dynamically-generated test functions into the module that called it.
- The fix had to land on `autobuild/FEAT-39E1` (worktree) rather than `main` because the
  master glue lives only on the autobuild branch; the focused glue's `importlib` load
  resolves only where the master is present.
